# Ifugao PPO BMI Monitoring System - Deployment Guide

## Overview
This document provides step-by-step instructions to deploy the Ifugao PPO BMI Monitoring App to Render.

## Architecture
- **Frontend**: React SPA served by Nginx, hosted on Render
- **Backend**: Django REST API served by Gunicorn, hosted on Render  
- **Database**: PostgreSQL (managed by Render)
- **Static Files**: Served via WhiteNoise middleware

## Prerequisites
- Git repository with this code pushed to GitHub (or GitLab/Bitbucket)
- Render.com account
- Google Authenticator app for admin 2FA (optional, but required for admin account)

## Local Development Setup

### 1. Backend Setup
```bash
cd backend
python -m venv .venv
# On Windows: .venv\Scripts\activate
# On macOS/Linux: source .venv/bin/activate
pip install -r requirements.txt
python manage.py migrate
python manage.py runserver
```

Backend will run on `http://localhost:8000`

### 2. Frontend Setup
```bash
cd frontend
npm install
npm run dev
```

Frontend will run on `http://localhost:5173`

## Production Deployment to Render

### Step 1: Push to Git Repository
Ensure your code is pushed to GitHub (or supported Git provider):
```bash
git add .
git commit -m "Production deployment ready"
git push origin main
```

### Step 2: Create Render Service
1. Go to [render.com](https://render.com) and log in
2. Click "New +" → "Blueprint"
3. Connect your Git repository
4. Select `main` branch
5. Review the `render.yaml` configuration
6. Click "Create" to deploy

The `render.yaml` will automatically:
- Create PostgreSQL database (`ifugao-bmi-db`)
- Deploy backend service with migrations
- Deploy frontend service with API URL from backend
- Configure environment variables

### Step 3: Verify Deployment
Once services are deployed:
1. Visit your frontend URL (e.g., `https://ifugao-bmi-frontend.onrender.com`)
2. Check backend health: `https://<backend-url>/api/admin/login/`
3. Monitor service logs in Render dashboard

## First Admin Account Setup

### Option A: Management Command (Recommended)
Once backend is deployed, run:
```bash
# Via Render Shell (use Render dashboard → Backend → Shell tab)
python manage.py createsuperuser
```

Or if you have access via SSH:
```bash
# Create admin user with forced password change
python manage.py shell
from api.models import CustomUser
CustomUser.objects.create(
    username='admin',
    is_staff=True,
    is_superuser=True,
    is_personnel=False,
    must_change_password=True,
)
# Set password manually with: user.set_password('TempPass123'); user.save()
```

### Option B: Direct Database Access
1. In Render dashboard, go to PostgreSQL database service
2. Use the provided connection string to connect (psql, DBeaver, etc.)
3. Insert admin user record:
```sql
INSERT INTO api_customuser (username, email, is_staff, is_superuser, is_personnel, must_change_password, password, last_login, is_active, date_joined, rank, rank_classification, birthdate, unit, sex)
VALUES ('admin', 'admin@ifugao-ppo.gov.ph', true, true, false, true, '', NOW(), true, NOW(), 'PBGEN', 'PCO', '1990-01-01', 'PHQ', 'Male');
```

### First Login Flow
1. Go to admin login page
2. Enter username: `admin`, temporary password
3. System will redirect to change password
4. Set new password (must be 8+ chars, alphanumeric, 1 uppercase, 2+ lowercase, 1+ digit)
5. On subsequent logins, you'll be required to scan QR code in Google Authenticator

## Environment Variables

### Backend (`render.yaml`)
```yaml
SECRET_KEY: Auto-generated by Render
DEBUG: False (production)
DATABASE_URL: PostgreSQL connection string (auto-set by Render)
ALLOWED_HOSTS: *.onrender.com,localhost,127.0.0.1
CORS_ALLOWED_ORIGINS: Frontend URL (auto-set from frontend service)
```

### Frontend (`render.yaml`)
```yaml
VITE_API_URL: Backend service URL (auto-set from backend service)
```

## Backup & Maintenance

### Database Backups
Render automatically maintains 1-week rolling backups. For extended retention:
1. Use Render's backup feature (available on paid plans)
2. Or manually export: Use `psql` to dump and store backup files

### Zero-Downtime Deploys
- Push code to `main` branch
- Render automatically rebuilds and deploys
- Previous version remains active until new version is healthy

## Troubleshooting

### Frontend not connecting to backend
- Check `CORS_ALLOWED_ORIGINS` in backend includes frontend URL
- Verify VITE_API_URL is correctly set in frontend build
- Check browser console for CORS errors

### Admin login page returns 404
- Ensure backend migrations ran successfully
- Check health endpoint: `GET /api/admin/login/`

### Password validation fails
- Password must be: 8+ chars, alphanumeric only (no special chars), 1 uppercase, 2+ lowercase, 1+ digit
- Example valid password: `Pass1234`

### Database connection errors
- Verify DATABASE_URL is set correctly
- Check database service is running in Render
- Ensure backend container has network access to database

## Security Notes

1. **SECRET_KEY**: Render auto-generates; never commit real keys to Git
2. **DEBUG**: Always set to `False` in production
3. **ALLOWED_HOSTS**: Should not include `*` in production (currently configured safely)
4. **CORS**: Frontend URL should be added for production
5. **HTTPS**: Render provides free SSL by default
6. **Admin 2FA**: Google Authenticator via TOTP for password resets

## Rollback

If deployment fails:
1. Render Dashboard → Service → Deployments tab
2. Select previous successful deployment
3. Click "Deploy"
